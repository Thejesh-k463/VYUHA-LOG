🏠

Runs on your computer

OpenAlgo is a program you install and run locally. Your broker credentials live in its .env file on your disk — never in Vyuha, never in any cloud.

📥

Vyuha only reads

Vyuha calls one endpoint (/api/v1/tradebook) and imports through the same preview → charges → duplicate-check pipeline as every file. It never places, modifies or cancels an order.

🔌

Off by default

The integration does not exist in the UI until you switch it on in Settings → Integrations (advanced) and accept an in-app disclosure.

1 · What you should know before enabling it (the honest part)

  • Your broker credentials go into OpenAlgo, not Vyuha. Vyuha stores only the OpenAlgo API key and the address of your instance — both revocable from OpenAlgo's own screen without touching your broker account.
  • The risk is real but small, and you should understand it: you are running one more program that holds a broker credential. The data itself only ever flows from your broker to your machine — OpenAlgo is a medium in between, not a service in the cloud. Keep it on 127.0.0.1 (Vyuha warns you before saving any non-local address, because at that moment your trade data would leave your computer).
  • Vyuha's pull is read-only: it calls one endpoint (/api/v1/tradebook), imports through the same preview → charges → duplicate-check pipeline as every file, and computes charges from your rate card — it never places, modifies or cancels an order.
  • Because of all of the above, the integration is off by default. You switch it on yourself in Settings → Integrations (advanced), after an in-app disclosure that states exactly this list. Your acceptance is recorded in the Audit Log.

2 · Install OpenAlgo on Windows

One OpenAlgo instance connects to one broker login. If you use two brokers through OpenAlgo, run two instances on different ports — Vyuha handles multiple instances side by side (section 4).

What you need first

  • Windows 10 or newer.
  • Python 3.12 or newer, installed with “Add python.exe to PATH” ticked.
  • Git for Windows (any recent version).

Install and first run

  1. Install uv (the Python runner OpenAlgo uses): 
    pip install uv
  2. Clone OpenAlgo into a folder of your choice: 
    git clone https://github.com/marketcalls/openalgo
cd openalgo
  3. Create your .env: copy .sample.env to .env and fill in your broker's lines (next section, and the per-broker deltas in section 9).
  4. Start it: 
    uv run app.py
    The first run takes several minutes — uv downloads and builds the whole environment. Later starts are quick.
  5. Open the dashboard at http://127.0.0.1:5000, create your OpenAlgo login, and complete the broker login (client id / PIN / TOTP as your broker requires). The dashboard should show your broker's name and Live Mode.
  6. Sanity-check before touching Vyuha: open OpenAlgo's own Tradebook page on a day you traded — your fills should be there. If they are not, Vyuha cannot see them either; fix the OpenAlgo side first.

Updating OpenAlgo later

  • Run install\update.bat from the OpenAlgo folder.
  • Some upgrades also need a database migration: 
    cd upgrade
uv run migrate_all.py
Full official documentation for every step: docs.openalgo.in → Getting Started / Connect Brokers.

3 · The .env file, decoded

Three lines connect an instance to your broker; everything else can stay at its default for a single instance:

BROKER_API_KEY    = 'the key your broker's developer portal gives you'
BROKER_API_SECRET = 'its secret (a few brokers do not use one)'
REDIRECT_URL      = 'http://127.0.0.1:<port>/<broker>/callback'

The <broker> segment of the redirect URL is OpenAlgo's short name for your broker (dhan, upstox, groww, paytm, kotak, angel, zerodha) — and the same URL must be registered on the broker's developer portal, port and all. A mismatch is the single most common setup failure.

Never rotate APP_KEY, the pepper or the salt. OpenAlgo auto-generates these encryption values in the .env on first run and uses them to protect every credential it stores. Changing them later destroys access to everything the instance has saved — logins, tokens, keys — and there is no undo. Leave them exactly as generated, and back the .env up as a whole.

4 · Running two or more brokers (multi-instance)

One instance, one broker login. For a second broker, run a second copy of OpenAlgo — the official way is the multi-instance.ps1 PowerShell script from the OpenAlgo docs, which sets up separate folders on ports 5000, 5001, and so on.

  • Separate folder per instance — each has its own .env, its own databases, its own auto-generated keys. Never share or copy these between instances.
  • Separate ports per instance — the second instance's .env carries its own set, for example: 
    FLASK_PORT=5051
HOST_SERVER=http://127.0.0.1:5051
WEBSOCKET_PORT=8766
ZMQ_PORT=5556
  • Separate API key per instance — each instance issues its own OpenAlgo API key, and each becomes its own row in Vyuha with its own host and port.

5 · The OpenAlgo API key

This is OpenAlgo's key, not your broker's. Get it from the instance's dashboard at /apikey (or the API Key menu entry).

a3f9…64 hexadecimal characters…c41e
  • It is a 64-character hex string, and it does not expire — it stays valid until you regenerate it from the same page.
  • Regenerating invalidates the old key immediately; you would then paste the new one into Vyuha's instance row.
  • Each instance has its own key. Pasting instance A's key with instance B's port is the classic mix-up — see Troubleshooting.

6 · The daily broker login

Broker sessions die around 3 AM IST, every day. Each morning (or before your evening pull), open the instance's dashboard at http://127.0.0.1:<port> and complete the broker login again — client id, PIN, TOTP, whatever your broker asks. Until you do, the tradebook is empty and a pull has nothing to read. This is a broker-side rule that applies to every broker API, not an OpenAlgo quirk.

7 · Connecting it to Vyuha

  1. Settings → Integrations (advanced) → switch OpenAlgo on → read the disclosure → Accept. The Import tab entry does not exist until you do, and the server refuses saves and pulls regardless of the UI — hiding a button is never the only defence.
  2. Import → OpenAlgo (self-hosted), then fill the three fields:
    • OpenAlgo API key — from section 5.
    • Host — http://127.0.0.1:5000, or whatever port that instance runs on. Each instance is its own host:port.
    • Broker behind OpenAlgo — the broker this instance is logged into. This matters: it stamps the trades and selects the charge profile.
    Then Add instance. Saving fires a live check against the instance, so a wrong key or port fails here with a message — not tomorrow at pull time.
  3. Repeat for a second instance — each appears as its own row with its own Preview / Pull & commit buttons.

8 · Pulling trades

  • Preview pull shows what would land — trades aggregated per contract, charges computed from your rate card — without writing anything.
  • Pull & commit imports through the normal pipeline. Everything that protects a file import protects this: exact re-pulls are skipped, a pull that adds nothing says so and lists what matched, and a suspicious overlap blocks the commit until you decide.
  • The tradebook covers the current trading day only — pull after you are done trading. Older history still comes in by file.

9 · Broker-by-broker: the exact deltas

Sections 2–8 are the same for every broker. What differs is where the API key comes from and what the daily login asks for. Two labels below tell you how far each path has been exercised:

✓ Verified live with Vyuha — a real pull from a real account landed real trades (Aug 2026)
◌ Documented, not yet exercised — the OpenAlgo path is official and published, but Vyuha has not run it against a live account

Dhan

✓ Verified live with Vyuha · Aug 2026
  • At web.dhan.co → DhanHQ Trading APIs, switch the app to API Key Mode (not the default partner mode) and set the redirect URL to http://127.0.0.1:5000/dhan/callback.
  • The .env key is a composite — your Dhan client id and the API key joined by three colons: 
    BROKER_API_KEY    = 'your_dhan_clientid:::your_dhan_apikey'
BROKER_API_SECRET = 'your_dhan_apisecret'
REDIRECT_URL      = 'http://127.0.0.1:5000/dhan/callback'
  • Daily login is a single click-through consent on Dhan's page.

Upstox

✓ Verified live with Vyuha · Aug 2026
  • Create a developer app at Upstox (account.upstox.com → My Apps / Developer API). The app gives you the API key and secret.
  • Set the app's redirect URL to http://127.0.0.1:<port>/upstox/callback — matching your instance's port exactly. Running Upstox as a second instance alongside another broker? Give it its own port (for example 5050) and register http://127.0.0.1:5050/upstox/callback.
  • Daily login is Upstox's standard OAuth page (mobile number / TOTP / PIN).

Groww

◌ Documented, not yet exercised with Vyuha
  • No app to create — Groww's execution platform portal issues a token pair (API key + secret) directly, which go into BROKER_API_KEY / BROKER_API_SECRET.
  • A static IP is mandatory. Groww's API requires you to whitelist the IP address your requests come from, so a home connection with a changing IP will break. This is a Groww-side requirement, and it is the one broker on this page where "install and go" is not enough.
  • Callback segment: groww.

Paytm Money

◌ Documented, not yet exercised with Vyuha
  • Create an API app at Paytm Money's developer page and choose the “Trading Bridge” app type.
  • The app is not usable immediately — wait until its status shows Active before putting its key and secret into the .env.
  • Callback segment: paytm.

Kotak Neo

◌ Documented, not yet exercised with Vyuha Most step-heavy of the seven
  • The .env fields carry different things than they do elsewhere: your UCC (Unique Client Code) goes in as the key, and an access token generated from the Neo developer dashboard goes in as the secret.
  • Daily login asks for the most of any broker here: mobile/UCC, TOTP, and your trading PIN — budget an extra minute each morning.
  • Callback segment: kotak.

Angel One

◌ Documented, not yet exercised with Vyuha
  • Create an app at smartapi.angelone.in (SmartAPI). Only the API key is used — the API secret is not used; login is a TOTP exchange: 
    BROKER_API_KEY = 'your_smartapi_key'
REDIRECT_URL   = 'http://127.0.0.1:5000/angel/callback'
  • Enable TOTP on your Angel One account first (smartapi.angelone.in/enable-totp) — the daily login cannot complete without it.
  • Note the callback segment is angel — not angelone.

Zerodha

◌ Documented, not yet exercised with Vyuha
  • Create a Kite Connect app at developers.kite.trade; its API key and secret go into the .env, with redirect http://127.0.0.1:<port>/zerodha/callback.
  • Daily login goes through Kite's page and exchanges a fresh request token each day — OpenAlgo handles the exchange; you just complete the Kite login.
  • Vyuha also connects to Zerodha natively (file import and its own API path) — use OpenAlgo for Zerodha only if you prefer one pull screen for every broker.

10 · What it costs

As of Aug 2026: read-only tradebook pulls are free on all seven brokers. Creating the developer app or API key costs nothing at Dhan, Upstox, Groww, Paytm Money, Kotak Neo, Angel One or Zerodha, and the tradebook endpoint Vyuha reads is not a paid add-on anywhere. The paid tiers some brokers advertise cover live market-data streams — not required for anything on this page.

11 · Troubleshooting

Each of these was hit in real testing.

SymptomCause and fix
"Cannot reach OpenAlgo at …" The instance is not running, or the port in Vyuha's Host field is not the port in the instance's .env. Check the OpenAlgo console banner — it prints its real address.
"wrong API key?" on save The key is the OTHER instance's, or was regenerated. Copy it again from that instance's API Key page.
A pull returns no fills on a trading day Log into the OpenAlgo web UI first — broker sessions expire daily and the tradebook is empty until the day's login.
A row is REFUSED with "suspect symbol" OpenAlgo's broker plugin mislabelled a contract (it has happened: a stock option arrived named as a silver option). Vyuha refuses to book a trade under a corrupt identity — import that one trade from the broker's own file or API instead.
A warning says a quantity was "recovered from trade value" Some OpenAlgo broker plugins report quantity 0 on real fills. Vyuha recovers the size from value ÷ price, tells you, and refuses any row it cannot recover. Check those against your contract note once.
